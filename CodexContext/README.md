- 위 ZIP 설명은 최초 문서 작성 당시의 조사 범위다. 현재 로컬 저장소에는 `Source/`, `.uproject`, `Config/`, `Content/`가 존재한다.
- 별도의 현재 분석 기준은 Git 커밋 `c3f94a967a9d7e756af659c53747208fda1a21fd` (`c3f94a9`)이다. 이 P0 정정은 해당 기준을 설명하는 미커밋 문서 변경이며, 기준 커밋의 내용을 소급 변경하지 않는다.
- [ImplementationStatus의 현재 분석](ImplementationStatus.md#9-현재-git-저장소-분석--c3f94a9-기준)은 과거 ZIP 기록과 분리해 요구사항·승인·C++·에셋·실행 검증·미결정 사항을 기록한다.
- 소스 경로 확인은 전체 기능 완료, 실제 BP 적용값, 컴파일 성공, PIE/Steam 동작 성공을 뜻하지 않는다. 현재 분석에서 빌드·테스트·에디터 실행은 하지 않았다.

## 근거의 사용 순서와 승인 경계

1. **작업 권한:** 현재 사용자의 명시적 지시와 승인 범위를 우선한다. 문서를 읽거나 Git에 보존하도록 승인한 것은 문서 안의 모든 게임 규칙을 일괄 승인한 것이 아니다.
2. **현재 구현 사실:** 기준 커밋의 실제 C++와 Config에서 확인한 내용으로 기술한다. BP/DataAsset/맵의 실제 적용값은 해당 에셋 확인이 있어야 확정할 수 있다. C++ 기본값과 런타임 적용값을 혼동하지 않는다.
3. **설계 요구사항:** 확인 가능한 사용자 승인 원문이 있으면 출처와 범위를 붙인다. 원문이 없으면 `승인 이력 확인 필요(F)`로 남긴다. `GameplayRules`나 FeatureSpecs의 '확정/최종' 표현, 기술 문서의 '수정 완료', Git 커밋 자체는 승인 원문을 대신하지 않는다.
4. **보조·역사 근거:** `Docs/Design`, `Docs/Technical`을 설계·구현 설명으로 대조하고, Debugging/Refactoring/Performance/Verification 및 DevLog는 작성 시점과 조건을 구분해 참조한다. 과거 측정·검증 기록을 현재 버전의 실행 결과로 옮기지 않는다.

이는 구현 사실을 판별하기 위한 근거 체계다. **소스가 설계보다 최신이라는 이유로 목표 규칙을 덮어쓰거나, 설계 문서만으로 구현 완료를 선언하지 않는다.** 충돌은 양쪽 파일·함수·값과 함께 기록하고 사용자 결정 전까지 미결정으로 유지한다.

현재 P0 승인은 지정된 세 문서의 정확성과 근거 체계 정정에만 적용한다. E1~E10의 게임 규칙 확정, P1~P3, C++·에셋·Config 변경, Git 변경, 빌드·테스트는 포함하지 않는다.

## 작업 순서

(1) `AGENTS.md`와 이 폴더 문서 읽기 → (2) 현재 `Source/`, `Content/`, `Config/` 탐색 → (3) 설계 대비 실제 구현 차이 보고 → (4) 명시적 수정 요청 범위만 변경 → (5) 검증 로그와 근거 남기기.

**경고:** 이 문서들은 '확정된 설계 목표'를 정리한 것이지 현재 빌드가 모든 기능을 갖췄다는 인증서가 아니다.

위 경고의 '확정된 설계 목표'는 기존 문서의 자기서술이다. 개별 규칙의 사용자 승인 확인 여부는 별도 기록하며, 원문이 없으면 F를 유지한다. 기존 설계 원칙·게임 규칙은 이번 P0에서 변경하거나 새로 확정하지 않는다.
