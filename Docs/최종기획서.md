NPC 위장 유물 쟁탈 멀티플레이 게임 기획서

0. 문서 개요
프로젝트 유형
•	2~4인 온라인 멀티플레이
•	3인칭 시점
•	개인전
•	NPC 위장·심리전
•	유물 쟁탈
•	판정형 원킬 전투
•	근접 음성 채팅
•	파티게임 성격의 랜덤 이벤트

한 줄 소개
NPC인 척 연기하며 상대 진영의 유물을 훔치고, 다른 플레이어의 정체를 추리하는 멀티플레이 심리전 게임.

핵심 플레이 경험
플레이어는 NPC와 완전히 동일한 젤리 인간 외형으로 맵에 배치된다.
상대 플레이어를 외형으로 구분할 수 없기 때문에 다음 단서를 관찰해야 한다.
•	이동 방향, 점프와 달리기 타이밍
•	자세 변경, 감정표현
•	공격과 방어
•	퀘스트 수행 행동
•	음성 채팅
•	발소리
•	유물 습득 사운드
•	NPC와 다른 비정상적 움직임
•	구조물 뒤에 숨어 관찰하는 행동
플레이어는 자신의 정체를 숨기면서 상대 진영의 유물을 훔쳐 자기 진영에 등록해야 한다.

용어 통일 원칙
•	플레이어와 NPC의 캐릭터 콘셉트는 모두 “젤리 인간”으로 통일한다.
•	유물 승리, 정규 시간 순위, 연장전 진입, 선두 대상 스킬에서 사용하는 “보유 유물 수”는 모두 진영 상자에 등록 완료된 유물 수를 의미한다.
•	플레이어가 운반 중이거나 필드에 떨어져 있거나 공용 위치에 남아 있는 유물은 등록 유물 수에 포함하지 않는다.
•	문서와 코드에서는 모호한 “유물 보유 수” 대신 RegisteredRelicCount와 bIsCarryingRelic을 구분해서 사용한다.

1. 스토리 콘셉트
오래전부터 마을에는 하나의 금기가 전해 내려왔다.
"숲속 깊은 곳, 달콤한 향기가 나는 저택에는 절대 들어가지 마라."
사람들은 그저 아이들을 겁주기 위한 이야기라고 생각했다.
그러던 어느 날, 호기심 많은 아이들은 숲속에서 풍겨오는 달콤한 젤리 향기를 따라가다 오래된 저택을 발견한다.
저택 안에는 형형색색의 젤리와 과자가 가득했고, 배고팠던 아이들은 경계를 풀고 안으로 들어간다.
하지만 문이 닫히는 순간, 저택의 주인인 마녀가 모습을 드러낸다.
마녀는 아이들을 향해 미소를 지으며 주문을 외운다.
잠시 후, 아이들의 몸은 점점 투명하게 변하기 시작했고, 말랑말랑한 젤리 인간으로 변해버린다.
마녀는 웃으며 말한다. "이제 너희도 이곳의 주민이란다."
________________________________________
하지만 그곳은 단순한 저택이 아니었다. 저택 안에는 수많은 젤리 인간들이 살아가는 작은 마을이 있었다.
겉보기에는 모두 똑같은 젤리 인간. 누가 원래부터 이곳에 살던 주민인지, 누가 방금 잡혀온 인간인지
구별할 방법은 전혀 없다. 마녀가 만든 젤리 주민들은 모두 그녀에게 절대적인 충성을 맹세한 신하들이다.
만약 인간이라는 사실이 들키는 순간, 마녀에게 끌려가 영원히 자아를 잃은 진짜 젤리 주민이 되어 버린다.
그래서 살아남기 위해서는 평범한 젤리 주민인 척 행동해야 한다.
걸음걸이도, 행동도, 표정도, 모든 것을 젤리처럼 연기해야 한다. 조금이라도 수상한 행동을 하면
주변의 젤리 주민들이 이상함을 눈치채고 마녀에게 알릴 수도 있다.
________________________________________
그러나 저택에는 오래전부터 전해 내려오는 전설이 하나 있다. 저택 어딘가에 숨겨진 ○○(유물명 미정) 을 모두 모으면 저택을 봉인하고 있는 마법이 잠시 약해지며 현실 세계로 이어지는 문이 열린다고 한다.
하지만 그 문은 단 한 명만 통과할 수 있다. 누군가 탈출하면 문은 다시 닫히고, 남겨진 사람들은 영원히 젤리 인간으로 살아가야 한다. 
그래서 모두는 서로를 속이고, 기회를 엿보며, 아무 일도 없는 평범한 젤리인 척 연기한다.
과연 당신은 마녀의 눈을 피해 끝까지 정체를 숨기고, 유물을 모아 이 저택에서 탈출할 수 있을까?

2. 핵심 디자인 원칙
2.1 외형이 아닌 행동으로 정체를 판별한다
모든 플레이어와 NPC는 완전히 동일한 젤리 인간 외형을 사용한다.
다음 정보는 표시하지 않는다.
•	플레이어 닉네임
•	플레이어 ID
•	플레이어 머리 위 아이콘
•	상대 진영 표시
•	상대 스킬 상태
•	상대 유물 소지 여부
•	플레이어 외곽선
•	NPC 외곽선
플레이어는 오직 행동과 소리를 통해 상대의 정체를 추리해야 한다.

2.2 강한 행동에는 정체 노출 위험이 따른다
다음 행동은 플레이에 유리하지만 플레이어임을 들킬 수 있다.
•	달리기
•	연속 점프
•	공격
•	방어
•	퀘스트 즉시 수행
•	자세를 유지한 채 이동
•	감정표현
•	가짜 죽음
•	스킬 사용
•	음성 채팅
•	유물 습득
•	유물 등록

2.3 유물 정보는 제한적으로만 제공한다
평상시에는 다음 정보를 알 수 없다.
•	각 진영이 등록한 유물 개수
•	도난당한 유물의 원래 진영
•	유물을 운반 중인 플레이어
•	필드에 떨어진 유물의 원래 소유 진영
•	현재 등록 유물 최다 진영
플레이어는 직접 진영의 상자를 열거나, 사운드와 플레이 상황을 기억해 유물 분포를 추리해야 한다.

2.4 사망 후에도 추리 플레이가 계속된다
사망자는 즉시 게임에서 완전히 배제되지 않는다.
사망 후 시체 중심 카메라, 살인자 현재 시점, 자유 카메라를 통해 수상한 행동을 관찰하고 부활 후 다음 행동을 계획할 수 있다.

2.5 진영 정보와 캐릭터 정체를 분리한다
•	각 진영은 BaseSlot 0~3으로 관리한다.
•	월드에서는 색상만으로 구분하기보다 달, 별, 사탕 등 중립적인 문양 또는 기호를 사용한다.
•	본인 클라이언트에는 자신의 진영만 로컬 UI로 강조한다.
•	다른 진영이 어느 실제 플레이어와 연결되는지는 공개하지 않는다.
•	연장전 유물 수 공개도 “달 진영 2개”처럼 진영 기호 기준으로만 표시한다.
•	진영 정보가 특정 젤리 인간의 정체를 직접 알려주는 UI는 사용하지 않는다.

4. 플레이어 수에 따른 유물 규칙
4.1 전체 유물 수
전체 유물 수는 다음 공식을 사용한다.
전체 유물 수 = 매치 시작 플레이어 수 + 1
각 플레이어 진영에는 유물 1개가 배치된다.
남은 유물 1개는 공용 유물로 맵 중앙 또는 공용 구역에 배치한다.

공용 유물의 정확한 좌표는 맵 그레이박스와 플레이테스트 후 조정한다.
단, 다음 구조 원칙은 구현 전에 고정한다.
•	공용 유물은 모든 진영에서 비슷한 시간 안에 접근할 수 있는 중앙 공용 구역에 배치한다.
•	특정 진영만 일방적으로 유리한 직선 경로를 갖지 않게 한다.
•	공용 유물 시작 위치는 고정 제단 또는 사전에 배치한 공용 스폰 포인트 중 하나로 관리한다.
•	공용 유물은 시작 지점에서 바로 보이는지, 엄폐물 뒤에 있는지를 맵 테스트로 결정한다.

4.2 승리에 필요한 유물 수
매치 시작 인원	전체 유물	승리에 필요한 유물
2명	3개	3개
3명	4개	3개
4명	5개	4개
유물 승리 목표는 매치 시작 인원을 기준으로 결정하며 경기 도중 변경하지 않는다.

4.3 유물 수 계산 기준
유물 승리, 정규 시간 종료 순위, 연장전 진입, 현재 선두 플레이어 대상 스킬은 모두 진영 상자에 등록 완료된 RegisteredRelicCount만 사용한다.
상태	계산 포함 여부
진영 상자에 등록 완료	포함
등록 완료 후 보호 중	포함
플레이어가 운반 중	미포함
필드에 드롭됨	미포함
공용 위치에 존재	미포함
등록 상호작용 진행 중	미포함

5. 승리 및 패배 조건
5.1 유물 승리
플레이어가 자신의 진영 상자에 필요한 개수의 유물을 등록하면 즉시 승리한다.
등록 상호작용이 서버에서 완료되는 시점에 해당 플레이어가 Alive 상태여야 한다.
등록 진행 중 피격되어 사망하면 등록은 실패하고 유물은 바닥에 드롭된다.

5.2 전멸 승리
전멸 승리는 Match Rule Data의 bEnableEliminationVictory로 활성화 여부를 관리한다.
기본 규칙은 다음과 같다.

2인 경기
전멸 승리를 사용하지 않는다.
2인 경기에서는 반드시 유물 3개를 자기 진영에 등록해야 승리한다.

3~4인 경기
bEnableEliminationVictory가 활성화되어 있고 정상 접속 중인 플레이어가 3명 이상일 때 사용한다.
한 명을 제외한 모든 플레이어가 동시에 사망 상태가 되면 마지막 생존자가 즉시 승리한다.

생존 판정 기준
•	플레이어의 캐릭터가 서버에서 정상적으로 스폰되고 맵에 존재해야 Alive로 처리한다.
•	스폰 완료 전 Respawning 상태는 생존자로 계산하지 않는다.
•	캐릭터가 스폰된 뒤 SpawnProtected 상태가 적용된 플레이어는 생존자로 계산한다.
•	Dead, Spectating, Respawning, Disconnected 상태는 생존자로 계산하지 않는다.
•	연결 종료 플레이어는 사망자가 아니라 승리 판정 대상에서 제외된 플레이어로 처리한다.

예시
3인 경기에서
A 사망
B, C 생존

B가 C를 처치
→ A와 C가 동시에 사망 상태
→ B가 전멸 승리
리스폰까지 남은 시간이 짧더라도 판정 시점에 캐릭터가 아직 스폰되지 않았다면 사망 상태로 계산한다.

5.3 정규 시간 종료
정규 경기 15분이 끝났을 때 RegisteredRelicCount가 가장 높은 플레이어가 단독 1등이면 즉시 승리한다.
운반 중이거나 필드에 떨어진 유물은 순위에 포함하지 않는다.

5.4 연장전
정규 경기 종료 시 RegisteredRelicCount가 가장 높은 플레이어가 두 명 이상이면 3분 연장전을 시작한다.
연장전 시작 전에 각 진영의 등록 유물 개수를 5초 동안 공개한다.
표시는 진영 기호 기준으로만 하며 진영과 특정 캐릭터의 정체를 연결하지 않는다.
5초가 지나면 유물 개수 정보는 다시 숨긴다.
연장전에서는 기존 유물과 기존 규칙을 그대로 사용한다.
연장전 중에도 유물 승리와 활성화된 전멸 승리가 적용된다.
연장전 3분이 끝날 때까지 단독 승자가 결정되지 않으면 전원 패배한다.

스토리 결과
현실로 돌아가는 문을 통과할 한 명을 결정하지 못했기 때문에 문이 닫히고 모든 플레이어가 젤리 세계에 남는다.

5.5 동시 사건 판정 원칙
모든 승리 및 실패 판정은 서버에서 확정한다.
•	먼저 서버에서 처리된 유효 사건을 적용한다.
•	사건 적용 후 중앙 함수 EvaluateMatchResult를 한 번 호출한다.
•	매치가 Finished 또는 Aborted가 되면 이후 공격, 유물 등록, 스킬 요청을 무시한다.
•	액터 Tick 순서에 따라 승자가 달라지지 않도록 GameMode 또는 Match Manager에서 중앙 판정한다.

판정 우선순위
1. Match Aborted
2. Relic Victory
3. Elimination Victory
4. Regular Time Result
5. Overtime Result

예외
•	유물 등록 완료와 피격이 경합하면 서버에서 먼저 처리된 유효 사건을 기준으로 한다.
•	등록 성공이 먼저 확정되어 매치가 Finished가 되면 이후 피격은 승리 결과를 변경하지 않는다.
•	피격과 사망이 먼저 확정되면 등록 요청은 실패한다.
•	동일 서버 처리 순서에서 두 명이 마지막 유물을 등록하려 하면 먼저 서버가 승인한 등록만 성공한다.

8. 3인칭 카메라
8.1 기본 카메라
TPS 게임과 동일한 기본 3인칭 카메라를 사용한다.
•	카메라는 캐릭터 몸의 회전과 독립적으로 회전할 수 있다.
•	플레이어는 구조물 뒤에서 몸을 숨긴 채 카메라만 돌려 주변을 확인할 수 있다.
•	카메라는 벽을 통과하지 않는다.
•	벽에 가까워지면 카메라 거리가 자동으로 줄어든다.
•	공격 판정 방향은 카메라가 아니라 캐릭터가 바라보는 방향을 기준으로 한다.
•	플레이어는 공격하기 전에 실제 캐릭터 몸을 목표 방향으로 회전해야 한다.

8.2 몸 회전 규칙
•	일반 이동 상태에서는 이동 방향에 따라 캐릭터 몸이 회전한다.
•	정지 상태에서 카메라만 회전해도 몸은 자동으로 카메라 방향을 따라가지 않는다.
•	공격 입력 시 캐릭터가 카메라 방향으로 자동 회전하지 않는다.
•	공격은 입력 순간의 캐릭터 전방을 기준으로 실행한다.
•	자세 고정 상태에서는 캐릭터 몸이 회전하지 않는다.
•	자세 고정을 해제한 뒤 첫 이동 입력부터 몸 회전이 다시 적용된다.

10. 전투 시스템
10.1 판정형 원킬 전투
플레이어는 HP 기반으로 피해를 주고받지 않는다.
플레이어가 공격 판정에 적중하면 피해량과 관계없이 즉시 사망한다.
따라서 다음 데이터는 사용하지 않는다.
•	HP
•	Max HP
•	Attack
•	Defense 수치

10.2 공격 흐름
공격 입력
↓
서버가 공격 가능 상태와 쿨다운 검증
↓
공격 애니메이션 재생
↓
팔이 실제로 닿는 시점에 공격 판정 활성화
↓
벽과 장애물에 막히지 않은 공격 범위 내 모든 유효 객체 수집
↓
범위 내 플레이어 적중
→ 적중한 모든 Alive 플레이어 즉시 사망

범위 내 NPC 적중
→ 공격자 3초 스턴
→ 주변 NPC 비명

→ 범위 내 플레이어를 모두 사망 처리
→ 같은 공격에 NPC가 한 명 이상 포함되었으므로 공격자를 3초 스턴 처리

10.3 다중 대상 판정
•	한 번의 공격은 범위 안에 들어온 모든 유효 대상을 처리한다.
•	가장 가까운 대상 한 명만 선택하지 않는다.
•	여러 플레이어가 공격 범위 안에 있으면 모두 사망 처리한다.
•	여러 NPC가 공격 범위 안에 있어도 오인 공격 스턴은 공격 1회당 한 번만 적용하며 중첩하지 않는다.
•	플레이어와 NPC가 함께 적중하면 플레이어 사망과 NPC 오인 공격 스턴을 모두 적용한다.
•	공격 범위 안에 있더라도 공격자와 대상 사이에 벽이나 차단 장애물이 있으면 적중하지 않는다.
•	공격 판정은 캐릭터 전방과 실제 공격 애니메이션 타이밍을 기준으로 한다.

10.4 동시 공격
•	서로의 공격 요청이 경합하면 서버에 먼저 도착하여 유효 처리된 공격을 우선한다.
•	첫 번째 공격으로 상대가 사망하면 뒤늦게 처리되는 상대의 공격 요청은 Alive 조건을 통과하지 못하므로 무효화한다.
•	동일 네트워크 프레임처럼 보이더라도 최종 결과는 서버 처리 순서로 결정한다.
•	클라이언트 화면에서 먼저 재생된 애니메이션은 승리 판정의 기준이 아니다.

11. 방어 시스템
방어는 모든 플레이어가 시작부터 사용할 수 있는 기본 행동이다.
항목	값
방어 지속시간	1초
방어 쿨다운	10초
방어 가능 공격 수	1회
방어 방향	캐릭터 전방
유물 운반 중 사용	가능
자세 변경 중 사용	불가능

11.1 전방 방어 판정
•	방어는 360도가 아니라 방어자의 캐릭터 전방 범위에서 들어오는 공격만 막는다.
•	전방 판정은 방어자의 Forward Vector와 공격이 들어온 방향을 기준으로 계산한다.
•	정확한 방어 각도는 Combat Rule Data로 관리하고 전투 플레이테스트 후 조정한다.
•	후방과 방어 각도 바깥에서 들어온 공격은 방어 지속시간 중에도 막지 못한다.

11.2 방어 성공
공격 판정이 방어 시간 안에 들어오고 전방 조건을 만족하면 공격을 무효화한다.
•	방어 성공 여부와 관계없이 방어 상태와 전용 애니메이션은 설정된 1초 동안 유지된다.
•	방어 성공 즉시 방어 상태를 종료하지 않는다.
•	한 번의 방어 사용으로 막을 수 있는 공격은 서버 처리 순서상 가장 먼저 들어온 유효 공격 1회다.
•	첫 방어 성공 후 남은 방어 시간은 애니메이션과 상태가 유지되지만 추가 공격을 막을 수 없다.
•	방어 성공 시 공격자와 방어자 모두 짧은 경직 또는 밀려남 연출을 적용한다.
•	정확한 경직 및 밀려남 수치는 플레이테스트 후 조정한다.

11.3 방어 실패
•	방어 시간 동안 공격을 받지 않아도 방어 쿨다운은 정상적으로 소모된다.
•	후방 공격을 받거나 이미 방어 가능 횟수 1회를 소모했다면 즉시 사망한다.
•	방어 애니메이션은 성공 또는 실패와 관계없이 원래 지속시간을 유지한다.

11.4 방어 노출
방어 사용 시 다른 플레이어가 명확히 확인할 수 있는 전용 애니메이션과 효과를 재생한다.
NPC의 가짜 공격에 방어를 사용하면 해당 젤리 인간이 실제 플레이어일 가능성을 노출하게 된다.

12. 유물 시스템
12.1 유물 상태
유물은 다음 상태 중 하나를 가진다.
•	진영 상자에 등록된 상태
•	공용 위치에 배치된 상태
•	플레이어가 운반 중인 상태
•	바닥에 떨어진 상태
•	등록 보호 상태
유물 상태는 Relic 액터와 서버의 RelicManager가 단일 원본으로 관리한다.

12.2 상자 확인
플레이어가 진영 상자를 열면 현재 상자 안에 등록된 유물 개수를 확인할 수 있다.
•	자기 진영과 상대 진영 상자를 모두 확인 가능
•	상자를 확인한 플레이어에게만 개수가 표시됨
•	다른 플레이어가 같은 상자를 열면 그 시점의 서버 기준 개수가 표시됨
•	상자를 열어도 한 번에 하나만 가져갈 수 있음
•	다시 돌아왔을 때 유물 개수가 같다는 보장은 없음
•	상자 확인 정보는 해당 클라이언트에게 일시적으로만 전달하며 평상시 복제하지 않음

상자 행동 구분
•	InspectChest: 등록 유물 개수 확인
•	StealRelic: 상대 진영 상자에서 유물 하나를 습득하는 2초 상호작용

상자 열기 상호작용 시간:

12.4 자기 진영 유물

13. 스킬 시스템
13.1 공통 규칙
모든 플레이어는 게임 시작부터 동일한 모든 스킬을 보유한다.
스킬을 획득하거나 잃는 시스템은 사용하지 않는다.
각 스킬은 독립적인 쿨다운을 가진다.
쿨다운이 끝나면 다시 사용할 수 있다.
•	사망 중에도 쿨다운 진행
•	스턴 중에도 쿨다운 진행
•	관전 중에도 쿨다운 진행
•	유물 소지 중에는 스킬 사용 불가
•	유물을 내려놓거나 등록하면 스킬 사용 가능
•	부활 보호 중에는 스킬 사용 불가

13.2 스킬 사용 가능 UI
•	스킬 자체를 사용할 수 없는 상태라면 스킬 UI 전체를 “사용 불가” 상태로 표시하고 입력을 받지 않는다.
•	유물 운반, 사망, 관전, 스턴, 부활 보호 등 스킬 사용 금지 상태를 서버와 로컬 UI가 동일하게 반영한다.
•	상대 대상 스킬에서 랜덤 대상 방식과 선두 대상 방식이 모두 유효하지 않으면 스킬을 사용할 수 없다.
•	두 대상 방식 중 하나만 유효하면 스킬 사용은 가능하지만 대상 선택 UI에서 사용할 수 없는 선택지를 비활성화한다.
•	좌클릭 랜덤 대상만 사용할 수 없으면 좌클릭을 비활성화하고 우클릭만 선택 가능하게 한다.
•	우클릭 선두 대상만 사용할 수 없으면 우클릭을 비활성화하고 좌클릭만 선택 가능하게 한다.
•	사용 불가 선택지를 클릭해도 쿨다운은 소모하지 않는다.

13.3 상대 대상 스킬의 공통 지정 방식
상대에게 사용하는 모든 스킬은 별도의 시야 조건 없이 대상 후보를 계산한다.
스킬 입력 후 다음 두 방식 중 하나를 선택한다.
입력	대상
좌클릭	유효한 플레이어 중 무작위 대상
우클릭	현재 RegisteredRelicCount가 가장 높은 유효 플레이어
NPC는 스킬 대상이 되지 않는다.
대상 선택 시 다음 플레이어는 제외한다.
•	자기 자신
•	사망 중인 플레이어
•	관전 중인 플레이어
•	Respawning 상태인 플레이어
•	부활 보호 상태인 플레이어
•	동일한 상태이상을 이미 받고 있는 플레이어

유효 대상 예외
•	선택한 방식에 유효 대상이 없으면 해당 선택지는 사용 불가로 표시한다.
•	선택한 사용 불가 방식의 입력은 서버 요청을 보내지 않으며 쿨다운도 소모하지 않는다.
•	두 방식 모두 유효 대상이 없으면 스킬 전체를 사용 불가로 표시한다.
•	유효 대상이 없는 상태에서 다른 플레이어를 강제로 다시 랜덤 선택하지 않는다.

13.4 유물 최다 등록 대상 선택
스킬 사용자는 현재 RegisteredRelicCount가 가장 높은 플레이어의 이름과 위치를 알 수 없다.
UI에는 다음 문구만 표시한다.
현재 선두 플레이어에게 방해 효과를 적용합니다.

•	모든 플레이어의 RegisteredRelicCount가 0이면 모두 공동 선두로 처리한다.
•	최다 등록자가 여러 명이면 유효한 동점자 중 한 명을 무작위로 선택한다.
•	동점자 중 자기 자신과 사용 불가 상태 플레이어는 제외한다.
•	제외 후 유효한 동점자가 없으면 우클릭 선택지를 비활성화한다.
•	대상에게는 스킬 사용자의 이름을 표시하지 않는다.

14. 퀘스트 시스템
14.1 퀘스트 개념
퀘스트는 모든 생존 플레이어에게 동시에 주어지는 글로벌 행동 미션이다.
퀘스트는 플레이어에게 특정 행동을 요구함으로써 정체 노출 위험을 만든다.
예시:
•	20초 안에 점프 3회
•	30초 안에 총 3초간 달리기
•	감정표현을 3초간 재생
•	특정 자세를 일정 시간 유지
•	내용 보완 필요: 추가 퀘스트
14.2 퀘스트 심리전
퀘스트가 시작되자마자 행동하면 빠른 순위를 얻을 수 있지만 주변 플레이어에게 정체가 노출될 수 있다.
늦게 수행하면 정체 노출 위험은 낮아지지만 높은 쿨다운 복구 보상을 얻기 어렵다.
14.3 퀘스트 순위 보상
퀘스트 완료 순서에 따라 스킬 쿨다운을 복구한다.
순위	쿨다운 복구
1위	30%
2위	10%
3위	복구 없음
4위	복구 없음
실패	쿨다운 복구 없음
복구 대상이 모든 스킬인지, 가장 쿨다운이 긴 스킬인지:모든 스킬
복구 퍼센트가 최대 쿨다운 기준인지 현재 남은 쿨다운 기준인지: 현재 남은 쿨다운 기준


14.4 퀘스트 실패
제한시간 안에 퀘스트를 완료하지 못하면 해당 플레이어에게 실패 사운드가 발생한다.
실패 사운드는 남은 행동을 완료할 때까지 계속 발생한다.
예시:
퀘스트: 점프 3회
제한시간 안에 2회 수행
↓
실패 사운드 발생
↓
추가로 1회 점프
↓
퀘스트 완료
↓
실패 사운드 즉시 종료
사운드는 거리에 따라 감쇠된다.
주변 NPC와 플레이어가 섞여 있기 때문에 다른 플레이어는 정확히 어느 젤리에게서 소리가 발생하는지 추리해야 한다.
14.5 퀘스트 예외 처리
•	사망 중 퀘스트 처리: 모든 플레이어가 생존상태일때만 퀘스트 생성 중간에 사망 시 퀘스트 열외
•	스턴 중 퀘스트 제한시간 처리: 스턴중에도 제한시간 흐름
•	부활 보호 중 퀘스트 대상 포함 여부: 퀘스트 대상 제한시간 흐름
•	연장전 중 퀘스트 발생 여부: 연장전 중에는 퀘스트 없음
•	랜덤 이벤트 중 퀘스트 중첩 여부: 중첩 안됨
•	퀘스트 발생 횟수와 간격: 게임 당 2-3회 이내

15. NPC 및 AI
15.1 NPC 수
기본 NPC 배율은 10이다.
기본 설정에서는 다음 공식을 사용한다.
NPC 수 = 매치 시작 플레이어 수 × 10

로비에서 방장이 NPC 배율을 변경한 경우 다음 공식을 사용한다.
NPC 수 = 매치 시작 플레이어 수 × 로비 설정 NPC 배율

기본값 예시
플레이어	기본 NPC 배율	NPC
2명	10	20명
3명	10	30명
4명	10	40명

•	NPC 배율은 로비 매치 설정값으로 저장한다.
•	매치 시작 시 실제 플레이어 수와 NPC 배율로 최종 NPC 수를 계산해 FMatchRuleSnapshot에 고정한다.
•	경기 도중 플레이어가 연결 종료해도 NPC 수를 다시 계산하거나 제거하지 않는다.
•	로비에서 허용할 NPC 배율의 최소·최대 범위는 성능 테스트 후 확정한다.

15.2 NPC 목적
NPC는 직접적인 적이 아니라 플레이어가 숨어들기 위한 군중이자 잘못된 추리를 유도하는 요소다.

16. 랜덤 이벤트
16.1 공통 규칙
•	한 경기당 2~3회의 이벤트 발생 시도를 설정한다.
•	이벤트 발생 시점은 랜덤 시간이 아니라 고정된 경기 경과 시간을 사용한다.

•	이벤트 횟수가 2회로 결정되면 4분과 8분에 발생 시도한다.
•	이벤트 횟수가 3회로 결정되면 4분, 8분, 12분에 발생 시도한다.
•	각 시점에 발생할 이벤트 종류는 정전, 젤리패닉, 젤리 전염병 중 서버가 무작위로 선택한다.

•	이벤트 발생 3초 전에 경고
•	연장전에는 발생하지 않음
•	두 이벤트가 동시에 발생하지 않음
•	예정 시점에 모든 정상 접속 플레이어가 살아 있을 때만 이벤트를 시작한다.

18. 근접 음성 채팅
18.1 기본 원칙
생존 상태에서 음성 채팅의 청취 거리와 거리별 감쇠는 게임 월드 안에서의 플레이어 간 거리를 기준으로 한다.
플레이어의 실제 마이크 입력 크기는 가상 거리나 최대 청취 범위를 결정하는 데이터로 사용하지 않는다.
즉, 다음 규칙이 적용된다.
월드 안에서 가까운 플레이어
→ 크게 들림

월드 안에서 먼 플레이어
→ 작게 들림

청취 가능 범위를 벗어난 플레이어
→ 들리지 않음
플레이어가 실제로 목소리를 작게 내거나 크게 내는 것은 게임 시스템의 거리 계산을 변경하지 않는다.
플레이어는 이를 심리전으로 활용할 수 있다.
예시:
•	실제 위치와 다른 장소에 있다고 거짓말하기
•	가까이 있지만 일부러 작게 말하기
•	멀리 있는 것처럼 행동하기
•	다른 플레이어의 목소리를 따라 하기
•	랜덤 이벤트를 이용해 위치를 숨기기

18.2 표시하지 않는 음성 UI
다음 정보는 표시하지 않는다.
•	말하는 플레이어 이름
•	캐릭터 머리 위 음성 아이콘
•	정확한 음성 방향 UI
•	플레이어별 거리 수치
음성 채팅 여부를 통해 특정 월드 캐릭터가 플레이어라는 사실을 직접 표시하지 않는다.

•	전용 서버 미지원 또는 후순위
•	방장이 나가면 즉시 경기 종료

20.2 일반 플레이어 연결 종료
•	연결이 종료된 플레이어가 운반 중이던 유물은 현재 유효 위치에 드롭한다.
•	현재 위치가 유효하지 않으면 가장 가까운 RelicRecoverySpawnPoint로 복구한다.
•	연결 종료 플레이어의 진영 상자에 등록되어 있던 유물은 사전에 배치한 연결 종료용 RelicRecoverySpawnPoint 중 서버가 무작위로 선택해 스폰한다.
•	완전한 임의 좌표에는 스폰하지 않는다.

20.3 연결 종료 진영
•	연결 종료 플레이어의 진영은 월드에 그대로 존재한다.
•	해당 진영은 InactiveBase 상태로 변경한다.
•	InactiveBase에는 새로운 유물을 등록할 수 없다.
•	InactiveBase 상자에서는 유물을 훔칠 수 없다.
•	기존 등록 유물은 20.2 규칙에 따라 복구 포인트로 이동한다.
•	해당 진영의 시작 및 부활 지점은 비활성화한다.
•	상자 상호작용 시 “이 플레이어는 녹아서 사라졌습니다!” UI를 표시한다.
•	연결 종료 플레이어는 선두 계산, 승리 판정, 전멸 승리 판정에서 제외한다.

20.4 잔여 인원
2인으로 시작한 경기
한 명이 이탈해 한 명만 남으면 경기를 중단한다.

3~4인으로 시작한 경기
연결 종료로 남은 플레이어가 2명 이하가 되면 경기를 중단한다.
경기 중단 시 승자는 결정하지 않는다.
결과 화면에는 다음과 같이 표시한다.
플레이어 이탈로 경기가 중단되었습니다.

20.5 전멸 승리 판정
정상적으로 접속 중인 플레이어가 3~4명이고 bEnableEliminationVictory가 활성화된 동안에만 전멸 승리를 사용한다.
접속 인원이 2명까지 줄었으나 경기 중단 처리 전의 짧은 구간이 존재하더라도 전멸 승리를 판정하지 않는다.
Match Aborted 판정을 전멸 승리보다 우선한다.

24.5 가짜 죽음 판정
•	가짜 죽음은 살아 있는 플레이어 또는 NPC가 래그돌처럼 보이는 위장 행동이다.
•	가짜 죽음 중인 플레이어는 LifeState가 Alive이며 공격 Trace에 적중하면 즉시 사망한다.
•	가짜 죽음 중인 NPC는 일반 NPC로 판정하며 공격자에게 오인 공격 스턴을 적용한다.
•	실제 사망 래그돌은 공격 Trace를 막지 않고 공격 대상에서도 제외한다.
•	가짜 죽음과 실제 사망은 서버 상태값으로 명확히 구분한다.

24.6 물리형 움직임 구현 원칙

다만 플레이어 4명과 NPC 최대 40명 환경에서 항상 완전한 액티브 래그돌을 적용하는 것은 성능과 네트워크 동기화 위험이 있으므로 다음 하이브리드 방식을 우선 검증한다.
•	기본 이동: 애니메이션 기반
•	상체와 팔다리 흔들림: Physical Animation 또는 부분 물리
•	피격과 실제 사망: 전체 래그돌
•	가짜 죽음: 살아 있는 상태의 래그돌 연출
•	먼 NPC 또는 화면 밖 NPC: 물리 품질과 업데이트 빈도 하향
•	최종 적용 범위는 40 NPC 성능 테스트 후 결정

28.3 숨겨진 정보의 공개 범위
데이터	서버	본인 클라이언트	다른 클라이언트
진영별 RegisteredRelicCount	항상 보유	해당 클라이언트가 직접 상자를 확인하거나 연장전 공개 때만 전달	다른 플레이어의 상자 확인 정보는 전달하지 않으며, 본인이 직접 확인하거나 연장전 공개 때만 전달
본인 유물 운반 여부	항상 보유	본인 HUD에 전달	전달하지 않음
다른 플레이어 운반 유물 포인터	항상 보유	전달하지 않음	전달하지 않음
최다 등록 플레이어	항상 계산 가능	이름과 위치 없이 스킬 선택 가능 여부만 전달	전달하지 않음
퀘스트 진행도	항상 보유	본인에게만 전달	전달하지 않음
스킬 쿨다운	항상 검증	본인에게만 전달	전달하지 않음
경기 시간과 현재 이벤트	항상 보유	공개 복제	공개 복제
후반 유물 위치	항상 보유	공개 3초 동안만 전달	공개 3초 동안만 전달

•	UI에서 숨기는 것만으로 끝내지 않고 필요하지 않은 비공개 데이터는 클라이언트에 전달하지 않는다.
•	PlayerState와 GameState에는 모든 클라이언트가 알아도 되는 정보만 일반 복제한다.
•	상자 확인 결과는 요청한 클라이언트에게 임시 응답으로 전달한다.
•	평상시 RegisteredRelicCount는 서버의 RelicManager가 소유한다.

28.4 동시 상호작용
•	유물 하나는 동시에 한 명만 습득 또는 등록 예약 가능
•	서버가 먼저 승인한 요청이 InteractionReservation을 획득
•	예약 플레이어가 취소, 사망, 거리 이탈, 연결 종료하면 잠금 해제
•	완료 시 서버가 거리, 시야, LifeState, ActionState, 유물 상태를 재검증
•	두 플레이어가 같은 유물에 접근해도 클라이언트 완료 시간만으로 승자를 결정하지 않음

28.5 중앙 결과 판정
•	상태 변경 함수 내부에서 각자 승리를 확정하지 않는다.
•	유물 등록, 사망, 연결 종료, 시간 종료 후 EvaluateMatchResult를 호출한다.
•	한 번 Finished 또는 Aborted가 확정된 매치는 추가 결과 판정을 수행하지 않는다.

30.2 확정 완료된 항목
•	모든 캐릭터 콘셉트는 젤리 인간으로 통일
•	승리와 선두 판정은 RegisteredRelicCount만 사용
•	스폰 완료 후에만 Alive 처리
•	공격은 범위 내 모든 유효 대상을 처리
•	벽을 통과해 공격하지 않음
•	플레이어와 NPC 동시 적중 시 플레이어 사망과 공격자 스턴 모두 처리
•	방어는 전방만 적용
•	방어 성공 여부와 관계없이 지속시간 유지
•	동시 공격은 서버에 먼저 도착해 유효 처리된 공격 우선
•	SpawnProtected 대상 공격도 공격 쿨다운 소모
•	실제 사망 래그돌은 Trace를 막지 않음
•	가짜 죽음 상태는 공격 가능한 살아 있는 상태
•	사망 중 모든 플레이어와 음성 송수신 가능
•	사망 중 거리와 방향 정보 없음
•	부활 후 근접 음성으로 전환
•	초기 버전은 실제 과거 킬 리플레이 대신 시체 중심 카메라 사용
•	발소리 증폭은 최대 청취 거리를 늘리지 않음
•	대상 방식별 스킬 사용 가능 UI 적용
•	발자국 시스템 제거
•	NPC 수는 플레이어 수 × 로비 NPC 배율
•	랜덤 이벤트 발생 시점은 4분, 8분, 12분으로 고정
•	예정 시점 생존 조건 미충족 이벤트는 보정 없이 건너뜀
•	진영과 플레이어 정체 분리
•	연결 종료 진영 InactiveBase 처리

이 문서는 게임 규칙 → 필요한 데이터 → 네트워크 판정 → 클래스 책임까지 연결되도록 구성한다.
정확한 수치는 데이터로 관리해 플레이테스트로 조정하되 판정 의미와 데이터 소유권은 구현 전에 변경하지 않는다.

35. 최종 설계 원칙
•	정확한 거리, 시간, 확률, 각도는 데이터로 관리하고 플레이테스트로 조정한다.
•	승리 조건, 상태 전이, 동시 사건 우선순위, 정보 공개 범위는 구현 전에 고정한다.
•	같은 상태를 Boolean, Enum, Gameplay Tag, 컴포넌트에 중복 저장하지 않는다.
•	유물 상태와 RegisteredRelicCount는 RelicManager를 단일 원본으로 사용한다.
•	서버에서 확정되지 않은 공격, 방어, 스킬, 유물, 승리 결과를 클라이언트가 결정하지 않는다.
•	NPC 위장이라는 핵심 경험을 해치는 이름, 외곽선, 음성 위치, 유물 소지 표시를 제공하지 않는다.
•	기술 위험이 큰 음성, 다중 공격, 동시 유물 상호작용, 액티브 래그돌은 전체 구현 전에 작은 테스트 맵에서 먼저 검증한다.
