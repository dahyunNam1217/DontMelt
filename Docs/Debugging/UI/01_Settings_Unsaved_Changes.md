# 설정창을 닫을 때 변경값이 사라지던 문제

| 항목 | 내용 |
|---|---|
| 문제 | 여러 탭을 바꾼 뒤 적용하면 현재 탭만 저장됐고, 뒤로·Esc를 누르면 확인 없이 변경값이 버려졌다 |
| 원인 | 비교할 저장 기준값이 없었고, 하나의 호출이 "닫기를 요청한다"와 "닫아도 된다"를 동시에 의미했다 |
| 해결 | 저장값 스냅샷과 현재 입력값을 비교해 변경 여부를 계산하고, 모든 닫기 경로를 하나의 요청 → 확인 → 완료 흐름으로 모았다 |
| 관련 코드 | `UDMSettingsWidget::RequestClose`, `RequestCategory`, `CompleteClose`, `OnSettingsClosed` |

## 현상

`WBP_DMSettings`는 타이틀·로비·경기 중 Esc 메뉴에서 공통으로 쓴다. 한 번의 검수에서 서로 연결된 문제 네 가지를 찾았다.

- 사운드 탭을 바꾼 뒤 그래픽 탭에서 적용하면 **현재 탭의 값만** 저장됐다.
- 뒤로 또는 Esc를 누르면 저장하지 않은 변경값을 **확인 없이** 버렸다.
- 저장이 실패해도 메모리 값은 먼저 바뀌어 있었다.
- 위젯을 다시 Construct한 뒤에는 닫기 Delegate가 끊겨 있었다.

## 원인 추적

| 확인한 코드 | 문제 |
|---|---|
| `HandleApplyClicked()` | `SW_SettingsPages`의 활성 탭만 저장 |
| Slider·ComboBox 변경 이벤트 | 비교할 기준값이 없음 |
| `BTN_Back`의 `OnCloseRequested` | 부모 위젯이 이것을 **"닫힘 승인"** 으로 취급 |
| 인게임 Esc | Settings 위젯을 거치지 않고 부모가 직접 숨김 |
| Delegate 등록·해제 | `NativeOnInitialized`에서 등록하고 `NativeDestruct`에서 해제. `NativeOnInitialized`는 재Construct마다 호출되지 않는다 |

핵심은 **하나의 호출이 "닫기를 요청한다"와 "실제로 닫아도 된다"를 동시에 의미한 것**이었다. 그래서 확인창을 끼워 넣을 자리가 없었다.

## 해결

별도의 설정 Subsystem을 추가하지 않고, 현재 UI 입력값과 저장 기준값을 비교하도록 했다.

- `SavedValues`: 저장값을 UI에 반영한 직후 읽어 기록한다.
- `bHasPendingChanges`: 매번 비교해서 계산한다. 값을 바꿨다가 원래대로 되돌리면 변경 없음으로 돌아온다.
- Slider 비교에는 허용 오차를 둔다.
- 코드가 UI를 채우는 동안에는 `bIsPopulatingControls`로 변경 이벤트를 막는다.

닫기는 하나의 경로로 모았다.

```text
탭 변경 / 뒤로 / Esc
  → RequestCategory() 또는 RequestClose()
  → 변경값이 있으면 확인창
      ├─ 적용: 전체 탭 값 저장 성공 후 다음 동작
      ├─ 변경 취소: 저장값 복원 후 다음 동작
      └─ 닫기: 현재 입력값 유지
  → CompleteClose() / OnSettingsClosed
```

- 저장이 실패하면 이전 메모리 값으로 되돌린다.
- 타이틀·로비·인게임 부모는 `OnSettingsClosed`가 올 때만 위젯을 닫는다. 인게임 Esc도 이 경로를 탄다.
- `NativeOnInitialized` / `NativeDestruct`의 비대칭 Delegate 정리를 없앴다.

## 검증 방법

| 시나리오 | 확인할 결과 |
|---|---|
| 값을 바꿨다가 원래대로 되돌린 뒤 닫기 | 확인창 없이 닫힘 |
| 사운드·그래픽 탭 수정 후 한 번에 적용 | 두 탭 모두 저장 |
| 읽기 전용 저장 폴더 | 저장 실패 안내, 이전 값 유지 |
| 로비→경기→로비 반복 후 설정 열기 | 닫기 동작 정상 (Delegate 유지) |
| 확인창이 떠 있는 중 경기 종료 | 결과 화면이 우선하고 입력이 꼬이지 않음 |

## 정리

- "요청"과 "승인"을 분리해야 그 사이에 확인 단계를 넣을 수 있다.
- 변경 여부는 플래그로 누적하지 않고 **기준값과 비교해 계산**하면, 되돌린 경우까지 정확해진다.
- UMG 생명주기 함수는 호출 횟수가 서로 다르다. 등록과 해제는 같은 쌍의 함수에 둔다.
